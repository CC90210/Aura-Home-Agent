# Cross-runtime operating card (2026-09-27)

**Status:** adopted on branch `claude/operating-card-2026-09-27`, 2026-09-27.
**Reference:** Maven's ADR-0008, `../CMO-Agent/docs/adr/0008-cross-runtime-operating-card.md` (the decision this note applies to Aura), and the copy-paste kit `../CMO-Agent/docs/handover/CROSS_RUNTIME_OPERATING_CARD_KIT.md`.
**Seed:** `PERSONAL.md` (new). **Stampers:** `scripts/genome_sync.py` (copied byte-identical from Maven; shared substrate) and `scripts/pointer_sync.py` (Aura's copy; only the agent and repo name strings and the file table differ).

## What was decided

Every runtime entry point (`CLAUDE.md`, `AGENTS.md`, `OPENCODE.md`, `ANTIGRAVITY.md`, `GEMINI.md`) now opens, right after its H1 and its one-paragraph narration, with the same three shared blocks in this order:

1. `operating_card` — 45 numbered lines: who Aura is, triage, the three reads, the read-only commands that answer most asks, what the house runs by itself, the NEVER list (with the lock-and-thermostat rules first), the four-line report, what to do when unsure, and the model-tier rule for small or fast models.
2. `capability_map` — the "I want to... / run this / reads-writes" table. Every "Works now" row was run in a fresh copy of this repo with no secrets and no Pi on 2026-09-27; "Needs a key" rows name the key and whether the command actuates; "Not runnable here" rows say what they need.
3. `posting_cadence` — the one place the house's schedule is written down (Home Assistant automation times, the two systemd services, CI, and what is not live). The block keeps the kit's name on purpose: one stable name across the four sibling harnesses is worth more than a pretty one, and renaming it would mean editing the stamper's tests and the kit.

The three blocks live once, in `PERSONAL.md`, and are stamped byte-identical into the five entry points by `python scripts/genome_sync.py`. The `operating_card` block is also stamped into ten per-tool pointer files (`.cursor/rules/aura-operating-card.mdc`, `.windsurf/rules/`, `.clinerules/`, `.github/copilot-instructions.md`, `.roo/rules/`, `.kilocode/rules/`, `.continue/rules/`, `.junie/guidelines.md`, `.trae/rules/project_rules.md`, `.aider.conf.yml`) by `python scripts/pointer_sync.py`, so a tool that never opens `AGENTS.md` still wakes up as Aura. Both `--check` modes run in CI (`.github/workflows/validate.yml`, `validate-python` job) next to the existing harness-canonical test.

## Why (in plain English)

- **Aura had no seed.** Before today the only shared text in the five entry points was the two blocks the empire harness pins (`tool_discipline`, `untrusted_content`). Everything else was written five times by hand, so each AI tool read a different first page, and the pages disagreed with each other (one morning-routine time in `CLAUDE.md`, another in `brain/SCHEDULE.md`, a third in the YAML).
- **Ten tools read ten files, and none of those files existed.** Cursor, Windsurf, Cline, Copilot, Roo, Kilo, Continue, Junie, Trae and aider each open their own rules file. `CLAUDE.md` claimed those tools read `AGENTS.md`; they do not. An AI opened inside any of them had no identity, no NEVER list and no idea a wrong command moves a lock.
- **This repo runs a home.** A small or fast model, or a tired human at midnight, needs one short numbered card that says: read-only until CC says go; these commands are safe; these are not; here is how to hand the rest off. That card must be the first thing on the page, not paragraph forty.
- **The Pi has never been seen online from a dev machine** (`memory/MISTAKES.md`, MISTAKE-001; `bash scripts/health_check.sh` on 2026-09-27 printed `[FAIL] Cannot SSH into root@homeassistant.local`). The card therefore says "configured, not confirmed live" about every schedule and makes step 7 the only source of truth, so no model repeats "Phase 3 complete" as if it were a device state.

## How it works

- `PERSONAL.md` holds every `<!-- LOCKSTEP:name --> ... <!-- /LOCKSTEP:name -->` pair. `python scripts/genome_sync.py` replaces the content between the matching markers in each file listed in `genome.json` (`entry_points`; `mirror_dir` is empty because Aura has no generated mirrors). `--check` exits 1 on any byte difference.
- The two pinned blocks are reproduced in `PERSONAL.md` byte-identical to `.harness/LOCKSTEP_*.md` so the first stamp changed nothing in them and `tests/test_harness_canonical.py` stays green. They are still owned by the empire harness: change them only through it, never here.
- The empty marker pairs were inserted by hand once, at the line right after each file's H1 and narration; the stamp filled them. This is the one deliberate hand edit the mechanism allows.
- `python scripts/pointer_sync.py` reads only the `operating_card` block and writes it under a three-line header ("You are Aura inside <tool>. Read AGENTS.md for the full contract. This card is the minimum."). A pointer file that already exists without markers is never overwritten; the block is appended below it. `.aider.conf.yml` is YAML, so it is a static pointer (`read: [AGENTS.md]`) compared byte-for-byte. `scripts/test_pointer_sync.py` covers create, idempotence, drift, missing file, static drift, narration survival, malformed markers and `--help`, all in a temporary directory.
- Editing the card: change `PERSONAL.md`, then `python scripts/genome_sync.py`, `python scripts/genome_sync.py --check` (must print `CLEAN`), `python scripts/pointer_sync.py`, `python scripts/pointer_sync.py --check` (must print `CLEAN`). Card step 17 says the same.

## What stays per-runtime (not stamped, owned by each file)

- The H1 and the opening narration of each entry point (which tool this is, what it is good at).
- Runtime-specific sections: `CLAUDE.md`'s architecture walk-through, MCP setup and skills routing; `ANTIGRAVITY.md`'s IDE notes; `GEMINI.md`'s notes; `OPENCODE.md`'s shell-first notes; `AGENTS.md`'s YAML frontmatter and its tool table.
- The two pinned harness blocks (`tool_discipline`, `untrusted_content`): their content, byte for byte. The stamper replaces content between markers and never moves markers, and `tests/test_harness_canonical.py` finds a block by its markers too, not by its line. In `AGENTS.md` on `main` the pinned `tool_discipline` block sat above the H1, inside an unclosed frontmatter (`---` at line 1, closer at line 20), which pushed the card's opener to line 28; the card must open within the first 20 lines so a tool that reads only the top of a file still meets it. On 2026-09-27 the unpinned lines around that block were rearranged, not the block: the frontmatter now closes after its `clients:` line (line 4), the H1 and narration follow (lines 6 to 10), the three shared blocks come next (the `operating_card` marker at line 12, the card's heading at line 13), and the pinned block sits after them, byte-identical (same md5 as on `main` and as `.harness/LOCKSTEP_tool_discipline.md`; the harness test still passes). Why this and not a harness-owner change: the harness pins content, and the content did not change; only its neighbours moved. One thing for the harness owner to know: if a future harness stamper anchors on a line number instead of on the markers, this file has a different shape now.
- The pointer-file header (the tool name), owned by the `POINTER_FILES` table in `scripts/pointer_sync.py`.
- `.claude/skills/*.md` (scene-control, voice-debug, dashboard-dev), `brain/`, `docs/`, `skills/weekly-reflection/SKILL.md`: referenced by the card, not stamped by it.

## Open items (named, not fixed here)

- `AGENTS.md` layout: fixed on 2026-09-27 by moving the unpinned lines, not the pinned block (above). Nothing is owed to the harness owner unless its stamper anchors on a line number; this note is the record.
- `scripts/agent_genome.py` was not copied, although the capability map's "Not runnable here" row lists it among the files that arrive with the install. Evidence, from a temporary read-only copy run against this repo on 2026-09-27 and then deleted: G2 (entry points carry the seed) printed `5/5 entry points, blocks identical`, but G3 to G9 look for Maven/Bravo wiring that does not exist here (`brain/SOUL.md`, `brain/CAPABILITY_GRAPH.json`, `memory/PATTERNS.md`, `scripts/core/memory_retriever.py`, `scripts/agent_sleep.py`, `scripts/lib/claude_cli.py`, a `.claude/settings.json` guard chain), so the script exits 1 forever and would be exactly the dead script name the card removes. The one property it would prove here is already gated by `python scripts/genome_sync.py --check` in CI. - `voice-agent/pulse_check.py`, `weekly_reflection.py` and seven other voice-agent modules call a metered API key directly and carry a model ID string in code (card line 27 and 23 of Maven's). Known gap, not a licence.
- `BRAVO_SUPABASE_SERVICE_ROLE_KEY` in a home agent's `.env` is full-database-write scope for a read-only bridge: flagged to CC in the capability map.
- `scripts/health_check.sh` labels its checks x/9 while its summary counts 10; `scripts/setup/verify_install.sh` and `README.md` disagreed on its count until today. The scripts were not edited.
- The lockstep steps sit in CI's `validate-python` job, placed before its `Install dependencies` step on purpose: that step pulls PyAudio (a microphone library) which may not build on a GitHub runner, and the gates need only the standard library plus pytest. The job count stays at four so the card's step 18 stays true. Whether the job is green today is not re-verified from this machine (no CI run here).
